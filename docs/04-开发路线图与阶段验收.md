## 4. 验收用例（A1–A10）

| 编号 | 用例 | 步骤 | 通过标准 |
|---|---|---|---|
| A1 | 初始化 | 打开未版本化的论文目录 → 初始化 | 生成 rev1；原文件一个没少、没改；`.fvhelper*` 不出现在变更列表 |
| A2 | 变更识别 | 改 3 个、删 1 个、重命名 1 个 → 提交 | 详情准确标 A/M/D/R；统计数一致；重命名不被错记成"删+增"（或明示原因） |
| A3 | 版本还原 | 同一文件连续 3 版 → 分别导出 rev1/2/3 | 三份导出与当时内容**逐字节一致**（SHA-256 相同） |
| A4 | 仅文件导出 | 导出 rev2，模式=仅文件 | 目标目录无 `.fvhelper*`；文件齐全；Word/PDF 能正常打开 |
| A5 | 含元数据导出 | 导出 rev2 含元数据 → 拷到另一台电脑打开 | 能看到完整 changelist；可继续提交；历史仍可导出 |
| A6 | 特殊路径 | 中文名、空格、`！`、>260 字符、8 层嵌套 | 全部成功，或给出明确降级提示（不许静默失败） |
| A7 | 文件被占用 | Word 打开 docx 时提交 | 索引不损坏；跳过或明确提示；`~$` 锁文件不进版本 |
| A8 | 崩溃一致性 | 提交到一半 `taskkill /F` | 重启后索引完好或自动从 `.bak` 恢复；无半写；历史不丢 |
| A9 | 大目录性能 | 1000 文件 / 2GB | 首次提交 ≤ 60s、增量 ≤ 5s、打开列表 ≤ 1s（实测后回填） |
| A10 | 同步目录风险 | 目录在 OneDrive 同步中操作 | 有风险提示；不产生半写/双写；失败可重试 |

## 5. 阶段流转规则

1. 每阶段结束在 `phases\Px-*\README.md` 写"完成记录"（日期/完成项/结论/遗留），再进下一阶段。
2. 退出标准任一条不达标 → 不进入下一阶段；要跳必须记入 `docs\05` 决策表并写清原因。
3. 代码只往 `app\` 累加，阶段目录不复制代码。
4. 每阶段至少产出一份第三方可检查的东西（截图、CLI 输出、测试报告、验收记录）。
