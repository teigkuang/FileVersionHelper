# 01 需求规格说明

> 版本 v0.3 ｜ 2026-11-06 ｜ 状态：已确认（v0.3 吸收"多项目管理 / 扫描后提示提交 / 导出后他人可续作 / 文件与数据匹配校验"新语义）

## 1. 背景与问题

大学生写论文/报告时，版本管理方式是"另存为 + 改文件名"：

- 目录里堆 `论文_v1.docx`、`论文_修改版.docx`、`论文_最终版(2).docx`，不知道哪个是最后一版、哪次改了什么；
- 想找回"上一周那版绪论"只能靠翻文件；
- 发给导师要挑一个"干净"的版本，还得手动删掉一堆中间产物；
- Word 的自动恢复/云盘历史版本依赖联网或特定软件，换电脑就断。

本工具把这些收敛为"一个目录 + 一个数据信息文件"，版本历史随目录走。

## 2. 用户与场景

目标用户：本科生/研究生，单人写作，Windows 笔记本，非技术背景。

| 场景 | 描述 | 关键诉求 |
|---|---|---|
| S1 首次建库 | 打开一个已有论文目录，工具提示"未检测到版本库"，引导初始化并做第 1 次提交 | 不破坏原文件、不误删、说明清楚 |
| S2 日常提交 | 改完一轮（可能改 3 个文件、删 1 个、重命名 1 个），提交并写一句说明 | 快、变更看得懂、能只提交部分文件 |
| S3 回看历史 | 打开目录，列表里看到所有 changelist，点开看某次改了哪些文件 | 一眼看出"哪次改了什么" |
| S4 导出交稿 | 把某个版本导出成一个干净目录交给导师 | 只出文件，不带内部数据 |
| S5 换机/备份 | 把整个目录拷到 U 盘/另一台电脑，打开后历史仍在，并能继续提交 | 数据自包含、可迁移 |
| S6 恢复误改 | 论文被改坏了，回到上一版导出、覆盖回来 | 历史内容必须真实可还原 |
| S7 多项目切换 | 同一个软件里同时管"毕业论文""课程论文""文献综述"几个文件夹，点一下就能切 | 项目列表常驻、切换不重开软件、各项目历史互不干扰 |
| S8 线下改完回软件 | 在 Word 里改了两小时，回到软件点一下就能知道改了哪些文件，并决定是否提交 | 扫描快、改动清单看得懂、不点提交就不产生记录 |
| S9 分享给别人续作 | 把某次提交导出的文件夹发给同学/导师，对方用同一软件打开，能看到历史、能继续改、能继续提交 | 导出物自包含（含数据信息文件时）、打开即可用、两端数据不打架 |
| S10 校验一致 | 别人发来的文件夹被人手动改过文件，或 `.dat` 被替换过 | 打开/导出时能校验"文件与数据是否匹配"，给出明确结论

## 3. 功能需求

优先级：P0 = v1.0 必须；P1 = v1.0 尽量；P2 = v1.x 以后。

| 编号 | 需求 | 优先级 | 说明 |
|---|---|---|---|
| FR-01 | 打开/添加项目 | P0 | 用文件夹选择器把**一个文件夹**加为项目（`OpenFolderDialog`）；一个软件内维护**项目列表**（多个文件夹），路径去重；记住最近项目；路径非法/无权限/只读时明确提示；支持中文、空格、深层嵌套路径 |
| FR-02 | 识别与解析数据信息文件 | P0 | 读取 `.fvhelper.dat`（格式见 03 文档）；文件缺失→引导初始化为新项目；文件损坏→只读降级 + 提示从 `.bak` 恢复 |
| FR-03 | changelist 列表 | P0 | 每个项目独立的 changelist：展示 rev、说明、作者、时间、变更文件数、增/改/删统计；按时间倒序；支持关键字搜索（说明/文件名） |
| FR-04 | changelist 详情 | P0 | 点某条 changelist → 中间区呈现该次提交：说明/作者/时间/文件数 + 文件清单（相对路径、动作徽标 A/M/D/R、大小）；可复制路径；可全选复制清单 |
| FR-05 | 导出单版本 | P0 | 选择目标目录 → 选择"仅文件"/"文件+数据信息文件" → 还原该版本全部文件；进度与取消；目标非空时自动建子目录 `导出_<工程名>_rev<N>_<时间>` |
| FR-06 | 提交新版本 | P0 | 扫描工作区变更 → 勾选要提交的文件 → 填写说明（必填，默认给出上次说明模板）→ 记录**作者、说明、提交时间** → 写入内容库与索引（已确认：软件自己负责提交） |
| FR-07 | 工作区变更提示 | P0 | 选中项目后显示"上次扫描·上次提交"摘要；发现改动时给出**淡黄色提示条**"检测到 N 个文件有改动（修改 X/新增 Y/删除 Z）——是否提交为新版本？"；提供"重新扫描"；v1.x 再评估 `FileSystemWatcher` 实时提示（P1-V6 已实测事件偏多，需 1s 去抖） |
| FR-08 | 初始化版本库 | P0 | 对无版本库目录：写 `.fvhelper.dat` + `.fvhelper\`，把当前文件作为 rev1 提交 |
| FR-09 | 设置 | P1 | 作者名（用于记录"谁提交"，默认取系统用户名）、忽略规则（如 `~$*`、`*.tmp`）、大文件跳过阈值、导出默认选项 |
| FR-10 | 仓库维护 | P1 | 校验完整性（哈希复核）、备份（生成 `.bak`）、显示占用空间、清理未被引用的 blob |
| FR-11 | 只读兼容模式 | P1 | 打开别人给的、或用其他工具生成的 `.dat` 时，可浏览/导出但禁止写入 |
| FR-12 | 诊断与日志 | P1 | 操作日志 + 崩溃日志写到 `%LOCALAPPDATA%\FVHelper\logs`；可一键导出诊断包 |
| FR-13 | 项目管理（多项目） | P0 | 左栏常驻项目列表：`＋` 选文件夹新增、去重、选中即加载；显示项目名/路径/上次提交时间；支持移除（只移出列表，不删文件）、重命名（仅显示名）；项目路径失效时标记为"路径不存在"并允许重新指定 |
| FR-14 | 分享包续作 | P0 | 导出"文件+数据信息文件"得到的文件夹，在任一安装了本软件的机器上**打开即可用**：能看到完整历史、能继续编辑（线下改文件）、能被识别为改动、能继续提交，提交后形成新的 rev 续在原历史上。导出"仅文件"的包不含历史，打开时按"新项目"处理（可选"作为新起点"） |
| FR-15 | 文件与数据匹配校验 | P0 | 打开项目、点开某条 changelist、执行导出时，校验"索引记录的文件清单与哈希"是否能对上：①索引容器自身完整性（容器尾 SHA-256 + 尾魔数）②该 rev `tree[]` 中的每个 hash 在内容库中是否存在 ③（可选/按需）工作区当前文件与 head 记录的哈希是否一致。结论用绿条"已校验…一致"或红条"不一致 + 原因（缺文件/哈希不符/索引损坏）"呈现，绝不静默放过。校验口径与降级策略见 `docs\03` |

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 1000 个文件 / 2GB 目录：首次提交 ≤ 60s；增量提交（改动 10 个文件）≤ 5s；打开并列出 100 条 changelist ≤ 1s（实测后回填基线） |
| 可靠性 | 索引写入必须原子（临时文件 + 替换 + `.bak`）；进程被杀不产生半写文件；任何异常不得丢失用户原始文件 |
| 数据安全 | 只读用户文件，不移动/不删除源文件；删除动作仅记录在版本树里，实际操作永不删源 |
| 兼容 | Windows 10 1809+ / 11 x64；中文/空格/Unicode 文件名；路径长度 > 260 需验证并给出降级方案 |
| 易用 | 从打开目录到导出完成 ≤ 4 次点击；所有错误提示说"发生了什么 + 该怎么办" |
| 体积 | 绿色版解压后 ≤ 80MB；安装包 ≤ 50MB |
| 隐私 | 全程离线；不采集任何数据；不访问目录以外的路径 |

## 5. 明确不做（v1.0 排除）

- 云同步/多端同步、多人协作与冲突合并（论文场景单人为主，v1.x 再评估）。
- 行级文本 diff（docx 需解压取 XML，独立工作量，排 v1.1）。
- Git 仓库导入/导出、与 GitHub 互通。
- macOS/Linux 版本（架构上预留，v1.0 只做 Windows）。
- 论文查重、格式检查、AI 写作。
- 自动定时提交（可作为 v1.x 的"每日自动快照"）。
- 全文检索文件内容。

## 6. 验收口径

以 `docs\04` 的验收用例 A1–A10 为准，逐条实测通过才算该阶段完成；任何一条不过，不得进入下一阶段。

## 7. 已确认事项（2026-11-06）

| 问题 | 结论 |
|---|---|
| 是否已有既存的 `.dat` 格式/第三方工具产出 | **无**。格式由我们自研，见 `docs\03`（D-08） |
| 软件是否自己负责提交 | **是**。提交必须记录作者、说明、时间（D-02） |
| 交付形态 | **先绿色单文件 exe（MVP），后续再做安装包**（D-07） |
| 技术栈 | **C# + .NET 10 (LTS) + WPF**，self-contained 单文件发布（D-01 v0.2） |

## 8. v0.3 新增语义确认（2026-11-06 用户口述，界面骨架已实现）

| 问题 | 结论 |
|---|---|
| 左栏放什么 | **项目列表**，不是文件列表。`＋`=选一个**文件夹**作为项目（D-10） |
| 中栏内容 | 两态：选中项目 → 该项目的文件表（带状态着色）；点 changelist → 该次提交的详情（D-11） |
| 提交谁负责 | 软件自己：用户线下编辑 → 回软件扫描 → 提示是否提交 → 填说明提交 → 记录作者/时间 → 进 changelist（D-02 延续） |
| 导出与分享 | 可导出"仅文件"或"文件+数据信息文件"；**导出物给别人后，对方用同一软件打开可继续查看/编辑/提交**（D-12） |
| 数据匹配 | **需要能校验文件与数据是否匹配**（D-13，口径见 `docs\03`） |
| 界面基调 | 浅色简洁（硬要求），已落地见 `phases\P3-桌面界面\界面稿\主界面布局规范-v0.2.md` |
| 中栏形态 | **文件表格**（不做卡片流）：文件 / 状态（新增绿·修改橙·删除红）/ 大小 / 修改时间（D-14） |
| 扫描时机 | **选中项目自动扫 + 窗口切回自动扫（2s 去抖）+ 手动"重新扫描"**；不用 `FileSystemWatcher`（D-15） |
| 作者名 | **首次填写后保存，之后可在"设置"里改**；存 `%LOCALAPPDATA%\FVHelper\settings.json`（D-16） |
