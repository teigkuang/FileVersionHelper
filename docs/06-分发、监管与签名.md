# 06 分发、监管与签名

> 版本 v0.1 ｜ 2026-11-06 ｜ 回答"exe 是否受平台监管"

## 1. 结论

**不需要许可、备案或上架审核。** Windows 上自己编译的 `.exe` 可以直接分发，微软不审批、不登记、不收费（除非你要上 Microsoft Store，那是另一套流程，本项目不需要）。

**但会被"软监管"**——不是行政审批，是用户机器上的四道自动检查，会影响"别人能不能顺利双击打开"：

| 门槛 | 什么时候触发 | 用户看到什么 | 影响程度 |
|---|---|---|---|
| SmartScreen | 下载来的、无签名、下载量小的 exe | "Windows 已保护你的电脑"/"未知发布者" | 高（会挡住一部分人，需点"更多信息 → 仍要运行"） |
| 杀软/Defender | 无签名的新 exe；尤其**自解压壳（SFX）**、加壳、体积异常 | 拦截、隔离、报"木马嫌疑" | 高（比 SmartScreen 更难解释） |
| 企业/学校组策略、AppLocker | 校园机、公司机 | "已被系统管理员阻止" | 中（多见于机房，个人笔记本少） |
| Mark-of-the-Web（MOTW） | 从浏览器/微信/QQ 下载的文件 | 打开时各种安全提示；部分功能受限 | 中（右键属性 → "解除锁定"可解决） |

## 2. 为什么"绿色单 exe"反而更少被拦

| | 绿色单 exe | 安装包 exe |
|---|---|---|
| UAC 提权 | 不需要 | 需要（安装到 Program Files 时） |
| 写注册表/HKLM | 不写 | 写（卸载信息、文件关联） |
| 组策略拦截面 | 小（只是个普通程序） | 大（安装程序本身常被策略限制） |
| 杀软敏感度 | 低（就是一个普通 .NET 程序） | 中（安装器行为像"释放文件"，易被启发式盯上） |

所以我们先做绿色单文件 MVP 是对的顺序：**先让程序本体跑起来、被人用起来，再谈安装体验**。

## 3. 本方案对"被杀软误报"的具体规避

1. **不用自解压 SFX 壳**。Flutter 那套"7z SFX 拼单文件"是杀软高敏感形态，我们改用 .NET 官方 `PublishSingleFile`（本质是把程序集打包，非自解压安装器）。
2. **不打包可疑依赖**：不引未知来源的二进制、不做运行期下载/释放文件、不写启动项。
3. **体积正常**：60–80MB 的 .NET 自包含程序是常见形态，比 1MB 的"加壳小工具"更不像免杀样本。
4. **签名（后续）**：正式发布阶段买 OV 代码签名证书（约 ¥2000–4000/年，个人可申请但审核趋严；EV 更贵且需硬件令牌）。签名后 SmartScreen 提示会随"下载量/声誉"逐步消失，杀软误报也显著下降。
   - MVP 阶段**不签**：省成本，且自己人小范围传（U 盘、微信）本来提示就少。

## 4. 发布时的配套动作（P4/P5 执行）

- 产物旁提供 `SHA256SUMS.txt`（`Get-FileHash -Algorithm SHA256` 生成），让用户能自行校验。
- 下载页/README 写一句"本程序未做代码签名，出现'未知发布者'属正常，可核对 SHA-256"。
- 提供"解除锁定"图文说明（右键 → 属性 → 勾选"解除锁定" → 确定）。
- 若某台机器被杀软拦：先在杀软里加信任，或把文件放到非同步目录再运行（部分杀软对 OneDrive/网盘目录更敏感）。
- 不上架 Microsoft Store（要开发者账号、审核、打包 MSIX，与"绿色单文件"目标冲突）。

## 5. 一句话回答你

> exe 不用审批，随便发；难点不在"监管"，在"用户机器上的三道自动拦截（SmartScreen / 杀软 / 校园策略）"。这三道靠"不套壳 + 体积正常 + 后续签名 + 给校验值"来化解，跟技术栈无关，属于分发工程问题，已排到 P4。
