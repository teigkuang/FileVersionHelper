## 1. 草图怎么读

用户手绘草图（`草图\图标草图-用户手绘.jpg`）：

- 两张纵向错位叠放的纸张矩形，每张内部 2–3 条横线表示文字行；
- 右上角一只眼睛：椭圆轮廓 + 中心圆点 + 上方三道放射短线。

读法：**叠页 = 同一份文档的多个版本（有先后、有历史）；眼睛 = 软件一直在盯着文件夹，扫描并发现改动**。
合起来正是产品的核心闭环：线下改文件 → 回软件扫描 → 提示是否提交。这不是装饰性比喻，而是功能语义的直译。

## 3. 视觉规范（与界面同源）

| 项 | 值 | 说明 |
|---|---|---|
| 主色 | `#3B72F6` | 与界面唯一主色一致，图标内所有描边、文本行、瞳孔、射线都用这一个蓝 |
| 底 | `#F5F6F8` | 界面底色；圆角方块，圆角半径 = 边长 22% |
| 纸页 | `#FFFFFF` | 两页错位约边长 8%，页与页之间只靠细蓝缝分层，不加投影 |
| 圆角 | 统一小圆角 | 纸页圆角、方底圆角、射线端头同一套逻辑 |
| 禁止 | 渐变、多级阴影、高光、玻璃/金属质感、写实眼球、文字 | App 图标 16px 下文字必糊，品牌名只出现在窗口标题与界面里 |

## 4. 工程产出

| 文件 | 规格 | 用途 |
|---|---|---|
| `FvHelper.ico` | 6 档：256 / 128 / 64 / 48 / 32 / 16，32 位带 Alpha | exe 资源图标 + 窗口图标；SHA256 `357C15A9ED4E1EF07DDF1D4BFF4353061A123ED43FC1E8304D8252EA7AE312A4` |
| `FvHelper-1024.png` | 1024×1024 RGBA，四角透明 | 母版，后续做商店图 / 安装包 / 文档头图都从这里缩 |
| `FvHelper-256.png` | 256×256 RGBA | 文档与 README 用的展示图 |
| `候选\方案A/B/C-*.png` | 2048×2048 | 三个候选原图存档 |
| `草图\图标草图-用户手绘.jpg` | 1280×1707 | 用户手绘原图存档（微信临时目录里的原件已被本项目复制留存） |
| `发布版-带图标-主界面.png` | 1300×820 | 实跑截图，标题栏左边可见新图标 |

**尺寸策略**：256/128/64/48 由 1024 母版等比缩放（LANCZOS）；**32 与 16 是重新绘制的简化版**——去掉页内横线与三道射线，只留「一张纸 + 一只眼」，并把描边加粗到约边长 6%。原因：直接缩小时细线在 32px 以下会消失成一团灰。

**已知限制**：16px 下仍偏软（Windows 小图标通病），可辨"蓝纸 + 蓝点"，但认不出两道文本行。若后续要更硬，只能把 16px 画成纯色块剪影（纸 = 白色块 + 蓝边，眼 = 一个蓝点），需要时可以再补一版。

## 5. 挂接方式（代码位置）

- `app\src\FvHelper.Desktop\FvHelper.Desktop.csproj`
  - `<ApplicationIcon>Assets\FvHelper.ico</ApplicationIcon>` —— 编进 PE 资源，资源管理器 / 任务栏 / 快捷方式直接用这个
  - `<Resource Include="Assets\FvHelper.ico" />` —— 同时作为 WPF 资源，供窗口引用
- `app\src\FvHelper.Desktop\MainWindow.xaml`
  - `Window` 上加 `Icon="Assets/FvHelper.ico"` —— 标题栏左上角图标（其余窗口沿用 exe 默认图标）
- 源文件位置：`app\src\FvHelper.Desktop\Assets\FvHelper.ico`
