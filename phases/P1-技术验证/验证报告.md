## 2. V1–V6 结论表

| 编号 | 验证项 | 结论 | 说明与对策 | 影响 |
|---|---|---|---|---|
| V1 | 目录选择 `Microsoft.Win32.OpenFolderDialog` | **可用** | 自检模式下构造成功（`FolderName` 可读、`Multiselect` 可设置）；真实弹窗交互需人工点一次，留 P3 验收 | P3 |
| V2 | 长路径（>260 字符） | **可用，无需 `\\?\`** | 319 字符路径：建目录/写入/`FileInfo`/`File.Replace`/整树删除全部 OK（.NET 10 内部自动处理，即使注册表 `LongPathsEnabled=0`） | P2 |
| V3 | 文件被占用 | **读取可以，替换不可以** | `FileShare.ReadWrite` 共享读 OK；此时 `File.Replace` 抛 `IOException`（被占用）；`FileShare.None` 独占时连普通读取都失败 | P2 + P3 文案 |
| V4 | SHA-256 性能 | **够快，走并行** | 100 MB→468 ms；600 MB 串行 2420 ms、2 线程 1167 ms、4 线程 674 ms、8 线程 460 ms | P2 |
| V5 | 原子替换 `File.Replace` | **需按场景分流** | 目标存在→OK 且备份正确（`target=new`/`backup=old`）；目标不存在→`FileNotFoundException`（走 `File.Move`）；只读目标→`UnauthorizedAccessException`（清属性后重试 OK）；跨盘→`IOException` 不支持 | P2 |
| V6 | `FileSystemWatcher` 递归监听 | **能用，但事件重复** | 期望 Created 30/Changed 15/Deleted 10/Renamed 3，实测 **30/45/10/3**（总 88 个事件）；Changed 因 Size+LastWrite 重复触发 3× | P3 去抖 |

### 2.1 逐项原始记录

**V2 长路径**

```
LongPathsEnabled = 0
创建 >260 目录: OK
目标文件路径长度 = 319
普通路径写入: OK
\\?\ 前缀写入: OK
FileInfo 读取(普通路径): OK len=2
File.Replace(长路径): OK，替换后长度=11
删除 >260 目录树: OK
```
→ 结论：`docs\03` 里"统一加 `\\?\`"这条**取消**。理由：.NET 10 已经自己处理了；自己再加前缀反而会让 UI 上显示的路径带 `\\?\`、也容易和 `File.Replace` 的组合参数打架。`app.manifest` 的 `longPathAware` 保留（成本为零，给非 .NET 路径的第三方组件兜底）。

**V3 文件占用**

```
FileShare.ReadWrite 共享读打开: OK len=9
共享读占用中 File.Replace: 失败(符合预期) IOException: The process cannot access the file because it is being used by another process.
FileShare.None 独占打开: OK
独占时普通读取: 失败(符合预期) IOException
独占时 File.Replace: 失败(符合预期) IOException
枚举到 ~$ 锁文件: 是
```
→ 这是本阶段**最重要的一条产品约束**：用户在 Word 里开着论文时点"提交"，**替换会失败**。必须在提交前预检可写性，而不是写一半崩掉（见 I-03）。

**V4 哈希性能**

```
100MB 单文件 SHA-256: 468 ms（约 214 MB/s）
300×2MB（共 600MB）: 串行 2420 ms / 并行 2 线程 1167 ms / 4 线程 674 ms / 8 线程 460 ms
```

**V5 原子替换**

```
A 目标存在+备份: OK target=new backup=old
B 目标不存在 File.Replace: 失败(符合预期) FileNotFoundException
B 回退 File.Move: OK
C 只读目标 File.Replace: 失败 UnauthorizedAccessException
C 清属性后重试: OK
D 跨盘(C:→D:) File.Replace: 失败(符合预期) IOException: 无法将替换文件移到要被替换的文件
```

**V6 监听**

```
期望: Created=30 Changed=15 Deleted=10 Renamed=3（合计 58 次操作）
实测: Created=30 Changed=45 Deleted=10 Renamed=3（事件总数 88）
```
→ Created / Deleted / Renamed 一个不少（**不丢事件**），Changed 重复 3×（写文件同时触发 Size 与 LastWrite）。所以：可以只把监听当"有变化"的信号，实际比对仍按哈希，并按路径 1 s 去抖。

## 3. 落到实现的决定（P2 / P3 必须照此写）

| 编号 | 决定 | 依据 |
|---|---|---|
| I-01 | **单文件发布方案确定，不启用 WinForms 回退**：体积 58.83 MB，远低于 100 MB 回退线；发布参数固定为 `-r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=None -p:DebugSymbols=false` | §0 |
| I-02 | **长路径不手工加 `\\?\`**；`SafePath` 只做"拒绝 `..`/绝对路径/盘符/保留字符/符号链接"的规范化，不做前缀拼接 | V2 |
| I-03 | **提交前批量预检可写性**：对每个 A/M 项以 `FileShare.None` 试开一次，失败即"跳过并列入占用清单"，UI 提示"请关闭 Word/PDF 后重试"；**不允许**提交到一半报错留半套索引 | V3 |
| I-04 | **读旧版本内容一律用 `FileShare.ReadWrite\|Delete`**（被占用也能读出内容做哈希），避免"文件开着就无法记录快照" | V3 |
| I-05 | **写 `.dat` 分两条路**：目标已存在 → `File.Replace(tmp, dat, dat.bak)`；首次创建 → `File.Move(tmp, dat)`；若抛 `UnauthorizedAccessException` → 清只读属性后重试一次，再失败即中止并保留 `.bak` | V5 |
| I-06 | **不做跨盘写入**（`.dat` 与 `.fvhelper\` 必须同目录，这也是格式设计的前提）；用户把目录设成网络盘/同步盘时给提示 | V5-D / R-12 |
| I-07 | **哈希并行**：线程数 `min(8, Environment.ProcessorCount)`；≤1 MB 的小文件批量并行、>64 MB 的大文件单独串行并显示进度 | V4 |
| I-08 | **监听 + 兜底**：`FileSystemWatcher` 只作"有变化"信号，按路径 1 s 去抖；窗口重新获得焦点、或每 5 s 定时做一次增量哈希比对作为兜底 | V6 |
| I-09 | **忽略规则**：`~$*`、`*.tmp`、`.fvhelper\`、`.fvhelper.dat`、`.fvhelper.dat.bak` 一律不进 changelist | V3 / docs\03 |
| I-10 | **V1 弹窗交互**留给 P3 人工验收（自动化无法点击系统对话框），但 API 可用性已证 | V1 |

## 4. 残留风险（进 `docs\05`）

| 项 | 现状 | 处理 |
|---|---|---|
| 提交时文件被占用 | 无法替换（实测 IOException） | 走 I-03 预检 + 文案，属"可解释的失败"，非硬伤 |
| 单文件首启 1.33 s | 比二次启动慢约 0.6 s（原生库解压到 `%TEMP%\.net`） | 可接受；手册注明"首次启动稍慢"；P4 再评估是否关闭压缩换启动速度 |
| 杀软/SmartScreen | 未实测（本机未触发） | P4 打包阶段实测并抓图 |
| 开发期非 self-contained 运行 | 本机系统目录只有 .NET 8 运行时，**.NET 10 runtime 只在 `D:\IDE\dotnet`**，直接跑 `bin\Release\...\FvHelper.exe` 会弹"需安装 .NET" | 开发期用 `D:\IDE\dotnet\dotnet.exe run --project ...`，或设 `DOTNET_ROOT=D:\IDE\dotnet`；交付物本身是 self-contained，不受影响 |
