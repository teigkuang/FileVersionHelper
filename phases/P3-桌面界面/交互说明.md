# 交互说明（P3 现状版）

> 用途：把"每个按钮点下去发生什么、失败怎么说人话"写清楚，便于自查和后续补功能时对口径。
> 对应实现：`app\src\FvHelper.Desktop\MainWindow.xaml(.cs)`（+ `PromptWindow` / `ExportDoneWindow` / `AuthorSettingsWindow` / `ExportWindow` / `AppSettings`）。所有版本操作都走 `FvHelper.Core`，界面不自己算任何哈希或索引。

## 一、启动与项目

| 入口 | 行为 | 失败时 |
|---|---|---|
| 启动 | 读 `%LOCALAPPDATA%\FVHelper\projects.json` 加载项目列表，并恢复上次窗口位置/大小（`ui-state.json`）；自动选中第一个项目并扫描 | 两个文件读失败都只是"当没记过"，不阻断启动；异常写 `logs\app.log` |
| 左栏 `＋`（Ctrl+O） | `OpenFolderDialog` 选一个文件夹 → 去重后加入列表并立刻扫描 → 存进 `projects.json` | 选到同一个文件夹：直接选中已有条目，不重复添加 |
| 点左栏某个项目 | 中栏切到"项目文件视图"，自动扫描一次；右栏换成该项目的 changelist | 文件夹不存在/无权限：`Repository.Open` 抛 `RepositoryException`，状态栏红字 + 中文弹窗 |
| 项目条目下方小字 | `上次提交 rev N · 时间`；没有版本库时显示"尚无提交记录"或"尚未扫描" | — |

**新文件夹不强制"初始化"**：没有 `.fvhelper.dat` 时按空项目打开，所有文件显示"新增"，第一次提交时自动建库（rev1）。

## 二、扫描（D-15 口径）

| 触发 | 说明 |
|---|---|
| 选中项目 | 立即扫一次 |
| 窗口重新激活（从 Word 切回来） | 距上次自动扫描 ≥2 s 才扫；2 s 内的反复切换合并成一次 |
| 点「重新扫描」（F5） | 强制扫一次 |
| 提交成功后 | 自动再扫一次（这次是"手动"口径） |

扫描只比较 `(size, mtime)`，命中 `.fvhelper\state.json` 缓存则跳过哈希——**只是打开文件没保存，不会被算成修改**。
扫描期间底栏按钮禁用、状态栏显示"正在扫描…"；扫描结果写回：

- 状态行：`上次扫描（自动）11-06 20:12 · rev 3 · 共 3 次提交 · 5 个文件`
- 有改动时中栏顶部出现淡黄提示条：`检测到 2 个文件有改动（修改 1 / 新增 1 / 删除 0 / 改名 0）——填好说明后点「提交新版本」。`
- 文件表格按 修改 → 新增 → 删除 → 改名 → 无变化 排序，状态列着色（修改橙、新增绿蓝、删除红、改名蓝、无变化灰）
- 有文件被别的程序占用（比如 Word 正开着）：照常显示，但状态行标注，提交时按 `Warnings` 提示（P2 的 I-03 口径：占用的不跳过，避免"以为提交了其实少一个文件"）

## 三、提交

| 情况 | 行为 |
|---|---|
| 说明为空 | 「提交新版本」按钮禁用，鼠标悬停提示"先填写本次修改说明" |
| 没有改动 | 按钮禁用，提示"没有需要提交的改动" |
| 首次提交且没设署名 | 先弹「设置」填版本信息署名（保存到 `settings.json`），取消则中止提交 |
| 点提交 | 按钮禁用 + 说明框只读 → 中栏盖上半透明进度遮罩（`正在提交 N 个文件…`，不确定进度条）→ 后台 `Repository.Commit(message, author, includePaths)`（提交前内部先跑 L1–L3，MISMATCH/CORRUPT 直接拒绝） |
| 提交确认窗（`CommitWindow`） | 点「提交新版本」先弹窗：列出**这次要提交的文件**（动作/文件/大小，默认勾选的都列上）+ **标题**（预填底部输入框，必填）+ **详情**（多行，可留空）；右下「取消」「提交」。标题为空时「提交」置灰并提示"标题不能为空"。取消则什么都不提交 |
| 成功 | 中文提示框：`已提交 rev N：<标题>／版本信息署名 X · N 个文件 · 大小`；随后清空说明框、刷新提交记录、重扫、右栏定位到新版本、中栏切到该版本详情 |
| 失败 | 弹窗 `提交失败：<原因>`，日志记堆栈，随后重扫保持界面与磁盘一致 |
| 部分文件提交 | 只提交**勾选**的改动：表格首列 32px 勾选框（缺省全选），黄条右侧「全选」「全不选」，黄条文案带 `已选 N 个待提交`；未勾的改动不落库、留在工作区，下次扫描仍显示"修改" |
| 一个都没勾 | 点提交时弹提示"没有勾选任何改动。勾上要提交的文件，或点「全选」" |
| 数据与内容不匹配 / 数据损坏 | 整库校验条为红/深红时「提交新版本」直接禁用，悬停提示"数据与内容不匹配（或数据损坏），先修好再提交" |

| 「打开文件目录」 | 顶栏（"重新扫描"左边）：用资源管理器打开当前项目的文件夹，方便直接改文件。文件夹不在了会提示"把它放回原位，或从列表移除后重新添加" |
| 「重新扫描」 | 立即重扫一次（也支持选中项目自动扫、切回窗口 2 s 去抖自动扫） |

## 四、提交记录（原 changelist）与提交详情

| 入口 | 行为 |
|---|---|
| 点右栏某条 | 中栏切到"提交详情"：标题 `rev N · 标题`；副行 `版本信息署名 · 时间 · N 个文件 · 大小`；动作表（A/M/D/R 着色）；自动跑一次 `Verifier.CheckCommit`（存在性+大小） |
| 版本详细信息区 | 导出条**上方**常驻一块：标题、详情（没填时灰字"（这一版没有填写详情）"）、`版本信息署名 · 时间`、`rev N（上一版 rev M）· 版本文件共 K 个 · 这一版改动 X 项`、`本次改动：新增/修改/删除/改名统计 · 合计大小 · 版本标识 <id>` |
| 校验条 | 四态：绿 `✓ 已校验：该版本记录的文件与版本信息一致（文件数、大小、哈希全部匹配）`；灰 `· 数据本身没问题；工作区和这个版本不完全一样`（WARN，正常）；红（MISMATCH，带 `Problems` 明细）；深红（版本信息损坏，带明细）。校验异常也会显示红条而不是崩掉 |
| 「重新校验」 | 深哈希重算（`deepHash=true`），慢一些但能发现"大小对、内容被换" |
| 双击某行文件 | 按 `Path` 用 `explorer.exe /select` 定位到资源管理器；文件已不在时提示"可能被改名或删除，可导出这一版" |
| 右键 / Ctrl+C | 右键菜单「在资源管理器中定位」「复制本次提交清单」；`Ctrl+C`（焦点不在说明框时）把 `rev + 标题 + 详情（有才写） + 版本信息署名/时间/文件数/总大小 + 每行 动作\t路径\t大小` 写进剪贴板 |
| 「返回文件列表」（Esc） | 回到项目文件视图 |

整库校验条（项目文件视图顶部）：扫描时同时跑 `Verifier.Check(root)`，四态文案
`✓ 版本信息自检通过（容器 / 索引 / 内容库 / 工作区 四层一致）`、`· 版本信息完整；工作区与最新提交有差异（正常，等你提交）`、红色 MISMATCH、深红 CORRUPT（带 `Problems`）。红/深红时同时禁提交与禁导出。

> **术语（P4 口径）**：界面上一律叫"**版本信息**"（设计文档里的"数据信息文件/数据信息"）、"**版本信息署名**"（原"作者"）、"**提交记录**"（原 `changelist`）。

## 五、导出

| 入口 | 行为 |
|---|---|
| 「导出（仅文件）」 | 选目录 → 引擎在目标下建 `导出_<项目名>_rev<N>_<yyyyMMdd-HHmmss>_仅文件`（重名加 `-2`）→ 只写文件，不含任何 `.fvhelper*` |
| 「导出（含版本信息）」 | 先弹确认框（可勾"作为新起点：只保留这一版，版本号从 rev1 开始、所有文件记为新增"）→ 选目录 → 导出文件 + `.fvhelper.dat` + 内容库；目录名结尾为 `_含版本信息`（勾了新起点则是 `_含版本信息-新起点`） |
| 完成 | 弹 `ExportDoneWindow`：`✓ 导出完成（模式）` + 摘要（`N 个文件 · 大小 · 已复制 M 个内容块`）+ 只读路径框（可选中/整段复制）+ 三个按钮：`复制路径`（点后变"已复制"并禁用）、`打开文件夹`（关窗后由主窗口开资源管理器）、`完成` |
| 导出中 | 中栏进度遮罩 `正在导出…`，两个导出按钮同时禁用 |
| 失败 | `导出失败：<原因>`。引擎在写任何文件之前做预校验，缺一份内容就整体中止，不会留下半套 |
| 分享出去之后 | 对方用同一 exe 打开那个文件夹 → 看到完整提交记录 → 改文件 → 提交 → rev 继续增长（repoId 相同，D-12） |

**版本数据是隐藏文件**：`.fvhelper.dat` / `.bak` / `.tmp` 与 `.fvhelper\` 都带 Windows `Hidden` 属性，资源管理器按默认设置看不到，用户只会看到自己的论文文件；导出的"含版本信息"目录同理。老版本建的库，新版本打开一次就会被补打上。删掉它们等于删掉历史，所以界面上不提示路径、只在空态里说"版本信息（隐藏文件，资源管理器里看不到）"。

## 六、设置与日志

| 项 | 说明 |
|---|---|
| 顶栏「版本信息署名 X」+「设置」 | 设置弹窗三块：**版本信息署名**（必填；每次提交记进版本信息里）、**大文件提示**（阈值 MB，改动里有文件超过它，黄条会补一句"其中 N 个文件超过 X MB，提交和导出会慢一些"，不影响提交）、**导出默认项**（导出含版本信息时默认勾选"作为新起点"，记住上次选择）；另外只读展示当前项目的忽略规则 |
| 设置存储 | `%LOCALAPPDATA%\FVHelper\settings.json`：`Author` / `LargeFileWarnMb` / `ExportAsNewStart`（不写注册表；缺字段按默认，旧文件兼容） |
| 中栏标题旁「重命名」（或左栏有焦点时 F2） | 改列表里显示的名字（`PromptWindow` 单行输入，空值拒绝），不动文件夹、不动数据。左栏右键菜单已取消（"在资源管理器中打开"由顶栏「打开文件目录」承担，"从列表移除"由「－」承担，不再有"重新指定文件夹"） |
| 路径失效 | 打开项目遇 `DirectoryNotFoundException` → 左栏该条变红字"路径失效 —— 可从列表移除后重新添加"，中栏引导"放回原位 / 「－」移除后「＋」重新添加"，不弹通用错误框 |
| 拖文件夹进窗口 | 任意位置拖入一个文件夹即加入左栏并扫描（只接受单个文件夹；文件拖入无效） |
| 日志 | `%LOCALAPPDATA%\FVHelper\logs\app.log`，记"点了什么、结果如何、异常堆栈"；写失败不影响主流程 |
| 快捷键 | Ctrl+O 添加项目 / F5 重新扫描 / Ctrl+E 导出（详情态） / Esc 返回文件列表 / F2 重命名（左栏有焦点且不在详情态；也可点中栏标题旁的「重命名」）/ Ctrl+C 复制提交清单（详情态） |

## 七、还没做的交互（明确记下来，别以为坏了）

1. 提交/导出的**真正可取消**：引擎 `ct` 已贯通到 `Commit`/`Export`，但界面还没有 `CancellationTokenSource` 与取消按钮；当前遮罩上的进度条是不确定态，操作本身不可中断，所以没放"假取消"按钮。
2. 忽略规则**编辑**：规则存在 `.dat` 索引里（`Index.Ignore`），改它等于改已共享的数据语义（且会让"索引里有、工作区看不到"的文件产生歧义），需要单独设计与测试；设置页目前只读展示。
3. 五态里的 **ReadOnly** 态：叶子文件只读、目录不可写时，目前靠错误框而不是界面态提示。
4. 窗口过窄时左右栏折叠成抽屉；文件列宽固定 230，未随窗口自适应。
5. 变更勾选未做"按动作分组 / 未改动项折叠"（改动行已按状态排序，无变化行不带勾选框）。
