# P5 测试与发布

**阶段目标**：按"产品"标准验一遍，出 v1.0。
**周期**：14–18 有效工时 ｜ **状态**：未开始 ｜ **前置**：P4 退出标准达成

## 本阶段目录放什么

- `验收记录\A1-A10.md` —— 每条用例的操作步骤、实际结果、截图、是否通过
- `缺陷清单.md` —— 编号、级别、复现步骤、状态、修复版本
- `异常注入\` —— 断电/杀进程/磁盘满/只读/缺 blob 的复现脚本与结果
- `性能基线.md` —— 实测耗时与硬件环境
- `手册\` —— 面向学生的使用手册（5 页内）+ 常见问题

## 任务清单

### 1. 功能验收
- [ ] A1–A10 逐条实测（用例见 `docs\04` 第 4 节），一条一行记录
- [ ] 回归：上一阶段修过的缺陷全部复测

### 2. 异常注入
- [ ] 提交中途 `taskkill /F` → 索引完好或自动恢复
- [ ] 手工截断/改字节破坏 `.dat` → 走 `.bak` → 再破坏 → 只读降级
- [ ] 删除某个被引用的 blob → 导出时中止并说明缺哪个文件
- [ ] 目标磁盘写满 → 明确提示，已写文件不产生"看起来完整"的假象
- [ ] 目录内文件全部只读 / 目录只读

### 3. 性能基线
- [ ] 1000 文件 / 2GB：首次提交、增量提交（10 个改动）、打开列表、导出
- [ ] 记录硬件（CPU/内存/盘型）与数值，回填 `docs\01` 非功能需求表

### 4. 真实试用
- [ ] 用自己 2 个真实论文/报告目录跑一周
- [ ] 找 2–3 个同学试用，只观察不指导，记录"卡在哪、哪句话没看懂"

### 5. 发布
- [ ] 使用手册 + 常见问题（安装、`.fvhelper` 是什么、怎么备份、怎么换机）
- [ ] `CHANGELOG.md`
- [ ] `releases\v1.0.0\` 归档：安装包、绿色版、手册、校验值（SHA-256）
- [ ] 打 tag（若启用 git）

## 交付物

## 退出标准

- A1–A10 全部通过
- 无 P0/P1 级缺陷；P2 级缺陷有明确排期
- 一个没参与开发的人，只读手册能完成"初始化 → 提交 → 导出版本"
- 性能达到 `docs\01` 的基线（或已把基线改写为实测值并说明原因）
